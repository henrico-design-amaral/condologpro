# CondoLogOPS — Style Guide Resolver

Status: ACTIVE RESOLVER
Version: 1.0
Date: 2026-09-01
Authority: accepted current marketing implementation/assets + current project decisions + HenricoOPS visual governance

## Purpose
Make visual expression portable without inventing a new rebrand during architectural recovery.

## Brand/naming
- Semantic project name: `CondoLogOPS`.
- Legacy repository/domain strings may remain technical while migration is pending.
- Public copy should use the semantic name unless a technical/path reference is intended.

## Expression principles
- operational clarity and traceability;
- condominium/front-desk context must be immediately understandable;
- evidence/process before generic SaaS claims;
- restrained, professional and system-oriented rather than decorative;
- marketing may be expressive but cannot imply unsupported app maturity.

## Current visual source
Until a newer explicit Brand/Style decision exists, exact type/color/graphic choices are resolved from the current accepted marketing implementation and approved project assets. Historical mockups are evidence only and do not automatically define current style.

## Visual language
Where consistent with current accepted implementation, favor:
- clear process sequences;
- operational status/evidence motifs;
- readable contrast and hierarchy;
- product-specific visualizations rather than generic dashboard cards.

## Forbidden drift
- old `CondoLogPro` naming used as semantic authority;
- invented product screens/metrics;
- mixing unrelated identity systems;
- generic AI/SaaS neon/glass treatment chosen without authority;
- visual claims that suggest production availability without technical evidence.

## Validation
`DESIGN.md` + `DESIGN_SYSTEM.md` + A11Y + current marketing implementation are checked before visual acceptance. A new durable identity direction requires a recorded decision rather than silent provider choice.
